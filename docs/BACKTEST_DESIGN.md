# 回测系统设计（V1.0 草案）

> 适用体系：《A股投资分析体系》V1.5 第八章（回测验证机制）
> 状态：设计稿，未实现。本文只定义"怎么做"，不含实现代码。
> 起草：2026-10-23

## 0. 一页结论

| 问题 | 结论 |
|------|------|
| 要不要分钟级数据 | **不要**。体系是低频决策（持仓数天到数季），日线足够；分钟级要付费源且模拟不出盘口深度，投入产出比极差 |
| 数据量 | 全市场 10 年日线约 1,200 万行、压缩后 300–600 MB，本地完全可承受；分钟级约 29 亿行 / 30–80 GB，不做 |
| 用什么架构 | 自建**事件驱动**回测器（非向量化），因为规则依赖截面与时点数据 |
| 三条路径 | 前向纸面回测（不需要历史数据）+ 日线历史回测（主力）并行；分钟级不做 |
| 最大的风险 | 不是数据量，是**时点股票池、财报可见性、成交假设**三件事 |

## 1. 目标与非目标

**目标**

1. 验证《体系》中的可回测规则：5 范式评分卡、Blacklist/Whitelist、产业链瓶颈模块、主题阶段判定。
2. 给出与 Ch8 口径一致的指标（年化、夏普、最大回撤、胜率、盈亏比、命中率、覆盖率）。
3. 支撑样本内外切分，判断规则是否过拟合。

**非目标**

- 不做日内撮合/打板成交模拟（另立项目，需要分钟线 + 盘口）。
- 不做实盘下单接入。
- 不做高频或做市策略。

**为什么不用现成框架**

| 候选 | 不用的原因 |
|------|-----------|
| backtrader / vnpy | 撮合模型面向期货/加密，没有 A 股涨跌停、T+1、停牌、最小 100 股的默认实现，改造成本高于自建 |
| qlib | 自带数据与因子体系，但数据需自备全量、依赖重（torch/部分模型），且它的回测假设与我们的"事件驱动 + 截面规则"不匹配 |
| 向量化回测 | 截面规则（板块归属、龙虎榜、主题阶段）在向量化里极易算错时点，宁可慢 |

## 2. 数据仓设计

存储用 **SQLite**（单机、无运维、可直接用 pandas 读写）；历史深度目标 **全市场 2018-01-01 起**（覆盖 2018 熊市、2019–2021 牛市、2022–2024 熊市，满足 Ch8 的"一个完整牛熊周期"）。

### 2.1 表结构

```sql
-- 日线（不复权原始价 + 复权因子分开存，避免二次复权错误）
CREATE TABLE kline_daily (
  symbol TEXT NOT NULL,          -- 6 位代码
  trade_date TEXT NOT NULL,      -- YYYY-MM-DD
  open REAL, high REAL, low REAL, close REAL,
  pre_close REAL,
  volume REAL,                   -- 股（科创板为股，其余注意单位，入库前统一为股）
  amount REAL,                   -- 元
  adj_factor REAL,               -- 后复权因子（同日）
  is_suspended INTEGER DEFAULT 0,
  PRIMARY KEY (symbol, trade_date)
);

-- 每日股票池快照（解决幸存者偏差的核心表）
CREATE TABLE stock_pool_daily (
  trade_date TEXT NOT NULL,
  symbol TEXT NOT NULL,
  name TEXT,                     -- 当日简称（含 ST/*ST/XD 标记）
  board TEXT,                    -- 主板/创业板/科创板/北交所
  is_st INTEGER, is_suspended INTEGER,
  list_date TEXT, delist_date TEXT,
  total_mv REAL, float_mv REAL,
  PRIMARY KEY (trade_date, symbol)
);

-- 财务数据（按公告日索引，解决未来函数）
CREATE TABLE financial_asof (
  symbol TEXT NOT NULL,
  report_period TEXT NOT NULL,   -- 报告期，如 2024-03-31
  publish_date TEXT NOT NULL,    -- 公告日（可见性判据）
  update_time TEXT,              -- 入库时间（备用判据）
  item TEXT NOT NULL,            -- 指标名，如 revenue/roa/cfo
  value REAL,
  PRIMARY KEY (symbol, report_period, item)
);

-- 除权除息与公司行为
CREATE TABLE corporate_action (
  symbol TEXT, ex_date TEXT, type TEXT, ratio REAL, cash REAL,
  PRIMARY KEY (symbol, ex_date, type)
);

-- 主题/概念归属（见 §6 开放问题：历史归属可能不可得）
CREATE TABLE theme_membership (
  theme TEXT, symbol TEXT, bk_code TEXT,
  asof TEXT NOT NULL,            -- 该归属的生效日
  source TEXT
);
```

索引：`kline_daily(trade_date)`、`stock_pool_daily(trade_date)`、`financial_asof(symbol, publish_date)`。

### 2.2 数据源与更新

| 表 | 主源 | 备源 | 频率 |
|----|------|------|------|
| kline_daily | 新浪日线接口（已验证可用） | 东财 push2his（SSL 在代理下不稳） | 每日收盘后 |
| adj_factor | 新浪复权因子 | 东财 | 每日 |
| stock_pool_daily | 全市场快照（东财 clist）+ 退市名单 | a-stock-data 通达信盘后包 | 每日 |
| financial_asof | 新浪财报（含公告日/入库时间） | 巨潮公告 | 季报密集期每日 |
| corporate_action | 东财分红送转 | 巨潮 | 每日 |

更新任务挂 launchd（与现有 `close-scan`/`validate` 同机制），失败写日志、不阻塞。

### 2.3 时点原则（PIT, point-in-time）

1. 任何查询必须带 `asof`：`WHERE publish_date <= :trade_date`（财务）、`WHERE asof <= :trade_date`（主题归属）。
2. 复权使用**当日已知**的因子；未来的除权不参与当日价格计算。
3. 股票池用当日快照，**禁止用当前全量代码表回溯**。

## 3. 回测引擎设计

### 3.1 事件循环

```text
for T in trading_calendar(start, end):
    pool = load_pool(T)                      # 当日可见股票池
    if empty(pool): continue
    ctx  = Context(T, pool, db)              # 只暴露 <=T 的数据
    signals = strategy.generate_signals(ctx) # 返回目标组合/订单
    orders  = risk.filter(signals)           # 7.5/7.6 风险预算 + 组合约束
    fills   = match(orders, T+1)             # 次日开盘撮合
    portfolio.apply(fills, fees(T))          # 记账（T+1 冻结）
    record(T, portfolio)                     # 净值、持仓、换手、成本
```

### 3.2 成交模型（保守优先）

| 情形 | 处理 |
|------|------|
| 正常买卖 | **次日开盘价**成交（不用当日收盘，避免"收盘价可知"幻觉） |
| 一字涨停（open=high=low=涨停价） | **买入不成交** |
| 开盘涨停但盘中打开 | 允许成交，价格按开盘价 × (1+滑点) |
| 一字跌停 | **卖出不成交**，次日继续挂 |
| 停牌 | 不成交；复牌首日按开盘价 |
| 流动性上限 | 单票单日成交额 ≤ 当日成交额 × 10%；超出部分按比例缩量 |
| 最小单位 | 100 股取整 |

### 3.3 费用模型（与体系 V1.5 一致）

```text
买入：佣金 max(amount × 0.00025, 5) + 过户费 amount × 0.00001 + 滑点 amount × 0.001
卖出：印花税 amount × 0.0005 + 佣金 max(amount × 0.00025, 5)
      + 过户费 amount × 0.00001 + 滑点 amount × 0.001
```

### 3.4 风险与仓位

- 仓位由 `min(单票上限, R ÷ 止损幅度)` 决定（体系 7.5）；回测里止损幅度来自策略输出，缺失则该信号作废。
- 组合约束：`Σ(仓位×止损) ≤ 6%`、单行业 ≤30%（情绪/主题 ≤20%）——与 7.6 一致。
- 现金不足时按信号优先级排队，不融资、不加杠杆（首版）。

## 4. 防偏差清单（每份报告必须自检并附结果）

| 偏差 | 防护 | 自检方式 |
|------|------|----------|
| 幸存者偏差 | 股票池含退市/暂停上市 | 报告给出"区间内退市股票数"与"其中被策略触及数" |
| 未来函数 | 财务按公告日、主题归属按 asof | 随机抽 20 个交易日，人工核对当日可见字段 |
| 前视选股 | 标的池由**事前规则**生成（如"2020 年报主营构成"），规则写入报告 | 报告附标的池生成规则与生成日期 |
| 过拟合 | 参数 ≤5 个；样本内/外时间切分 | 给出参数敏感性表（±20% 变动下的指标变化） |
| 成本低估 | 费用 + 滑点 + 冲击 | 报告给出成本占收益比例 |
| 数据窥探 | 同一规则只允许在验证集上评估一次 | 记录评估次数与时间 |

**红线条**：任何一项自检不通过 → 该回测结论不得用于修改体系规则。

## 5. 评估口径（对齐体系 Ch8）

| 指标 | 最低 | 优秀 |
|------|------|------|
| 年化收益（扣费） | > 基准 +3% | > 基准 +10% |
| 夏普 | > 0.5 | > 1.0 |
| 最大回撤 | < 30% | < 20% |
| 胜率 | > 50% | > 60% |
| 盈亏比 | > 1.2 | > 1.5 |
| Blacklist 命中率 | > 70% | > 85% |
| Whitelist 命中率 | > 60% | > 75% |
| 数据覆盖率 | ≥90% 的样本占比 > 80% | — |

**分组输出**（缺一不可）：按范式、按资金规模（微型/小型/中型）、按市场阶段（牛/熊/震荡）。

**基准**：沪深 300、中证 500、对应行业指数三者同时对比。

## 7. 里程碑与验收

| 阶段 | 交付 | 验收标准 |
|------|------|----------|
| M1 数据仓 | 全市场 2018 至今日线 + 每日股票池 + 财务 asof | 随机 20 只票与新浪/通达信抽查一致；退市股覆盖 ≥95% |

| M4 全市场评分卡 | 5 范式截面回测 | 样本外达标，参数敏感性可接受 |
| M5 前向接入 | registry 注册体系规则 | 连续 3 个月每日自动验证无中断 |

## 8. 开放问题（实现前需定）

1. **概念板块历史归属**：东财当前归属未必能回溯；若不可得，则 Ch4 主题阶段与瓶颈模块在历史回测中只能降级为"当前归属 + 标注前视风险"。
2. **申万行业分类变更**：分类会调整，需用历史分类或固定代理（如行业 ETF），否则"行业中位数"会跨期不一致。
3. **龙虎榜/资金流历史深度**：东财接口一般只回看有限天数，长窗口回测需先确认可取范围。
4. **停牌与复牌**：长期停牌（>30 交易日）期间的估值与复权处理需单独定义。
5. **数据源合规**：东财/新浪属 C 级（仅个人研究），Yahoo 属 D 级；回测结果不得用于对外产品。
6. **复权与除权的时间点**：现方案用当日因子，需验证与交易所口径一致。

## 9. 风险与不做的事

- 不承诺"回测通过 = 实盘有效"：A 股风格切换快，样本外只做一次，更多依赖前向纸面回测积累。
- 不做分钟级：见 §0。
- 不用"当前成分"回溯历史：宁可少测一个主题，也不制造前视。
- 回测结果不进入对客材料（合规）。

## 10. M1 实施记录（2026-10-24）

- **换源**：东财 clist 在本机返回 0 条 → 全市场代码表改用新浪快照（5,576 只，同时提供名称与**当日成交额**）。日线：新浪主源、腾讯备源（手/股单位已适配）、东财仅 1 次尝试。
- **规模**：5,576 只 × 2018-02-27 ~ 2026-10-23 = **9,433,538 行**，**失败 0 只**，30.3 分钟（6 并发，3.1 只/秒）。
- **落盘**：`kline/*.parquet` 9 个 **123.4 MB**；`pool/*.parquet` 9 个 **28.4 MB**；`meta.db` 32 KB。合计 **约 152 MB**。
- **存储修订**：股票池原设计放 SQLite 每日快照，250 天就 109 MB、2,100 天约 900 MB → 改为 Parquet 按年分区（名称/板块字典编码），同数据仅 28 MB。
- **质量校验**：重复 `(symbol, date)` = 0；名称缺失 = 0；板块覆盖 沪主板 1699 / 深主板 1494 / 创业板 1409 / 科创板 616 / 北交所 353；最新日 `amount` 回填 5,571/5,571。
- **数据清洗**：发现并删除 **189 行零价占位**（920xxx 北交所代码在 2018–2020，新浪对"代码启用前日期"返回 0 价），已加 `close > 0` 过滤并补单测，股票池同步清理 189 行。
- **已知问题**：
  1. 历史成交额为空（新浪/腾讯日线均不含），只有最新交易日由快照回填 —— 流动性闸需要历史成交额时须先补源；
  2. 2026 年仅到 10-23，年度行数偏低属正常。
- **复现命令**：`python scripts/build_warehouse.py --universe --days 2100 --datalen 2100 --workers 6`

## 11. M2 实施记录（2026-10-24）

- **模块**：`tradingagents/backtest/engine.py`（事件循环 + 撮合 + 记账）、`metrics.py`（Ch8 指标）、`strategies.py`（BuyAndHold / PeriodicRebalance）、`scripts/run_backtest.py`（CLI + 校准模式）。
- **撮合规则落地**：T 日信号 → **T+1 开盘**成交；T+1 冻结（买入当日不可卖）；一字涨停不买、一字跌停不卖、停牌不成交；涨跌停按 ST 5% / 科创创业 20% / 北交所 30% / 其余 10%。
- **费用**：印花税 0.05%（卖）+ 佣金万 2.5（最低 5 元）+ 过户费 0.001% 双边 + 滑点 0.1%。
- **校准结果**（零成本 vs 解析解，3 个 ETF 案例）：

  | 案例 | 引擎 | 解析解 | 误差 |
  |---|---|---|---|
  | 512480 2020-07~2021-12 | −37.673% | −37.673% | 0.0000% |
  | 515880 2023-01~2024-06 | +38.914% | +38.914% | 0.0000% |
  | 512480 2021-01~2022-12 | −61.476% | −61.476% | 0.0000% |

  含费用一致性：512480 2023-01~2024-06 引擎 −15.078% vs 解析 −15.076%，误差 0.0019%。
- **测试**：`tests/test_backtest_engine.py` 6 例（零成本收益比、T+1、一字涨停、停牌、费用公式、回撤/成交统计）。
- **过程中修掉的 bug**：策略返回空 dict 表示"清仓"，引擎用 `if self._pending:` 判断会把空 dict 当"无信号"，导致永远不卖。已改为 `is not None` 哨兵，并补测试用例。
- **样例**：600519 2019-01-01~2024-12-31 买入持有 → 区间 +147.72%、年化 17.00%、夏普 0.68、最大回撤 −51.04%。
- **未做**：组合层风控（7.5/7.6 的 R 预算、行业集中度）尚未接入引擎；成交额历史缺失导致流动性闸暂不可用。

## 12. M3 实施记录（2026-10-24）——方向有支持，证据不成立

- 篮子：`tradingagents/backtest/baskets.py`；脚本：`scripts/run_bottleneck.py`（环节等权、区间收益、离散度）。

| 主题 | 事前判定瓶颈 | 瓶颈收益 | 最弱环节 | 离散度 | 瓶颈排名 |
|---|---|---|---|---|---|
| 锂电 2020-07~2021-12 | 上游锂矿 | **+273.12%** | 正极 +194.71% | 78.41pp | 第 1 |
| 算力 2023-01~2024-06 | 光模块 | **+357.27%** | 应用 +24.96% | 332.30pp | 第 1 |
| 半导体设备 2021-01~2022-12 | 设备 | **−11.02%** | 设计 −66.49% | 55.47pp | 第 1 |

**但必须打折看**：

1. **选股偏倚**：篮子按"今天已知的龙头"挑（赣锋/天齐、中际旭创/新易盛、北方华创/中微），是典型事后选股；
2. **锂电案例不成立**：终端（比亚迪 +269.97%）与瓶颈 +273.12% 仅差 3pp，"瓶颈跑赢终端"没有意义；
3. **单标的环节**（终端整车、电解液）个股特质压过环节特质。

**与 ETF 代理试点结论相反**（那里瓶颈跑输 −52.9pp）：差异来自代理口径——有色ETF 掺黄金铝、通信ETF 掺运营商，把瓶颈稀释了。**代理怎么选，结论就怎么变**，两边都不能当定论。

**判定**：支持"环节选择对收益影响大"这一方向，但**不足以证明瓶颈框架有效**，模块维持实验性。要变成证据还缺三件事：① 按事前规则建篮子（当年年报主营构成/市值排名）；② 退市股入仓（当前仓只有现存 5,576 只）；③ 以"时点信号真实出现"为入场条件，而非全程持有。
