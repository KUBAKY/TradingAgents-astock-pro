# TradingAgents-Astock 项目治理（GOVERNANCE）

> 本文件定义仓库的协作规则、变更流程、质量门禁与文档义务。
> 适用对象：维护者、贡献者、以及一切修改本仓库的 AI agent。

---

## 1. 双轨协作模型

| 轨道 | 场景 | 流程 |
|------|------|------|
| **个人本地轨** | 维护者个人使用的功能（短线系统、调度任务、个人环境脚本） | 直接 commit 到 main；每条提交通过测试门禁（§5） |
| **社区贡献轨** | 外部 PR / 上游同步 | GitHub 分支 + PR + 审查；合并前必须跑完整测试门禁 |

判定：改动是否只服务维护者个人环境（launchd plist、`.env`、`~/.*` 路径）？
是 → 本地轨，且**个人环境文件不入库**（§6.4）；否 → 社区轨。

## 2. 文档职责分工

| 文档 | 职责 | 何时更新 |
|------|------|----------|
| `README.md` / `README_en.md` | 对外说明：定位、架构、快速开始、配置 | 功能/配置对外可见变化 |
| `CLAUDE.md` | 项目知识库：架构、数据源、已知问题、注意事项 | 数据源、架构、已知问题变化 |
| `CHANGELOG.md` | 版本发布记录（Keep a Changelog 格式） | 每个版本发布时；重大未发布改动可先入 `[Unreleased]` |
| `DEV_LOG.md` | 开发进度与踩坑日记（阶段/周为粒度） | 每个功能批次完成后 |
| `docs/GOVERNANCE.md` | 本文件：治理规则 | 规则本身变化时 |
| `issues/NNN-*.md` | 单问题根因记录（编号递增） | 疑难 bug 修复后沉淀 |
| `CHANGES_FROM_UPSTREAM.md` | fork 相对上游的全部改动清单 | 与上游差异变化时 |

## 3. 变更流程（最小化）

```
1. 明确改动范围（一个 commit 一件事，原子提交）
2. 代码改动 + 同步测试（TDD：先 RED 后 GREEN，见 §5）
3. 跑全量门禁：pytest 基线确认
4. 更新受影响文档（§2 对应条目，改动即义务）
5. 提交（§4 格式），必要时更新 CHANGELOG
```

禁止：无测试改动直接提交、测试未跑就宣称完成、顺手夹带无关改动。

## 4. 提交约定

- 格式：`<type>(<scope>): <描述>`，type ∈ `feat|fix|refactor|docs|test|chore|perf|ci`
- 描述中文，动词开头，≤80 字符主题行；正文说明 **why**（背景/根因），不重复 diff 内容
- 一条提交一个逻辑变更；批量小修可合并，禁止把无关文件塞进同一提交
- 错误提交：用新提交修复，不 rewrite 历史（除非发布前整理）
- 功能批次如对应既定计划编号（如 ④-⑩），在正文标注，便于进度追溯

## 5. 质量门禁（提交前必过）

```
1. pytest 全量：基线 314 passed / 2 failed（上游 claude CLI 未登录所致，非本项目回归）
   新改动引入的任何失败都视为回归，禁止带着回归提交
2. 新增功能必须带测试（单元 ≥ 主路径 + 边界；数据层新增端点需实测连通）
3. 数据接口测试网络失败时：先确认是否网络/风控问题，再决定跳过与记录（不能悄悄删测试）
4. 变更涉及 LLM 调用：用 mock 或 --no-llm 路径验证 prompt 构造，避免真实调用污染测试
```

## 6. 工程红线

### 6.1 数据源访问
- 东财（eastmoney.com）**所有**请求必须走 `_em_get()`（限流+会话复用+随机抖动）；
  新增东财端点禁止裸 `requests.get`（CLAUDE.md 已知问题节有细则）
- 新增外部端点必须先实测连通与字段稳定性，再接入主流程
- 失败必须静默降级或明确标记（data_gaps），不得抛异常中断主流程

### 6.2 安全
- 禁止硬编码密钥/令牌；一律 `.env` 或环境变量
- 日志禁止输出敏感信息（密钥、token、完整报错中的凭据）
- 校验所有外部输入（ticker 等）再进入系统路径（`safe_ticker_component`）

### 6.3 不可变性
- 处理输入数据一律产出新对象，禁止原位变异调用方持有的结构
- 已有约定（如 `_AUCTION_CACHE` 记忆化、决策卡格式）保持向后兼容

### 6.4 个人环境文件不入库
- `.env`、`~/Library/LaunchAgents/*.plist`、个人日志、临时产物一律 gitignore / 不入库
- 个人调度任务（launchd）代码入 `scripts/`，plist 模板可入库为 `.example`，用户实际配置留在 `~`

## 7. 版本与发布

- 版本号：SemVer，0.x 内破坏性变更显式标注（CHANGELOG 格式沿用上游）
- 发布动作：版本号 bump + CHANGELOG 版本节 + 全量门禁 + 文档同步
- 对外可发布状态要求：README 可用、测试全绿（除上游 CLI 两例）、无未提交关键代码

## 8. 决策记录

- 重要技术选型写入 `DEV_LOG.md`「决策与选型记录」节（Why / How to apply）
- 疑难 bug 根因写入 `issues/NNN-*.md`，正文含：现象、根因、修复、防复发手段

## 9. AI agent 使用约定

- 修改代码后必须跑门禁；文档义务与代码义务等同（§2）
- 未授权不提交、不 push、不创建 PR；提交前 `git status` / `git diff` 自查
- 测试与实现分离：先写失败测试（RED）→ 实现（GREEN）→ 重构，检查点随阶段提交
- 涉及真实行情数据的窗口验证（竞价 09:15-09:30 等）只在实际窗口执行，其余时间用缓存/直调验证逻辑
